# Md Abir personal brand guidelines

This file is the source of truth for visual and written work representing Md Abir. Use it for websites, social-media cards, presentation covers, project thumbnails, portfolio graphics, profile banners, diagrams, and other personal-brand material.

If a request conflicts with this guide, follow the explicit request and preserve the brand principles wherever possible. Never invent achievements, employers, metrics, testimonials, or project results.

## Brand foundation

### Identity

- Name: Md Abir
- Primary professional descriptor: AI Automation Engineer
- Supporting descriptors: Data and AI Engineer, Product Builder, M.Sc. Data Science student
- Current positioning: builds digital solutions and automation for manual operational processes
- Location: Erlangen, Germany
- Initials: MA

### Brand idea

The brand communicates operational clarity: understand how work happens, turn the process into a reliable system, and show evidence of the result.

The visual and written tone should feel:

- precise and practical;
- technically capable without looking cold;
- confident without self-promotion;
- modern without depending on visual trends;
- grounded in shipped work, decisions, and measurable outcomes.

### Message hierarchy

Use this order when deciding what an asset should communicate:

1. The problem or operational constraint.
2. The system, product, or automation built to address it.
3. The evidence: a result, technical decision, or specific lesson.
4. The technologies, only when they help explain the work.

Do not lead with a long list of tools. Do not describe an exploration as a shipped product.

## Visual system

### Color palette

| Token | Hex | Use |
| --- | --- | --- |
| Ink | `#11130F` | Primary text, dark backgrounds, buttons |
| Soft ink | `#30342E` | Supporting text on light backgrounds |
| Paper | `#F1F0E9` | Primary warm background |
| Bright paper | `#FAF9F4` | Cards and alternate light sections |
| Cool paper | `#DDE1D8` | Technical grids and capability sections |
| Line | `#CDCFC5` | Dividers, borders, quiet structure |
| Muted | `#5F645B` | Secondary text on light backgrounds |
| Acid lime | `#CAFF3E` | Primary highlight, proof points, markers |
| Warm orange | `#FF7145` | Small identity accent and status detail |
| White | `#FFFFFF` | Text and surfaces where needed |

Approved high-contrast combinations:

- Ink text on Paper, Bright paper, Cool paper, or Acid lime.
- White text on Ink.
- Acid lime text or graphics on Ink.
- Soft ink or Muted text on Paper and Bright paper.

Do not use white text on Acid lime. Do not use Acid lime for long text. Warm orange is a micro-accent, not a large background color. Do not add gradients unless the deliverable explicitly calls for one.

### Color proportion

A typical asset should use approximately:

- 70–80% Paper, Bright paper, or Ink as the base;
- 15–25% supporting neutral surfaces and lines;
- no more than 5–10% Acid lime and Warm orange combined.

The accent colors should direct attention, not decorate every element.

### Typography

Primary typeface: **Manrope**

- Use weights 600–800 for headlines.
- Use weights 400–600 for body text.
- Use tight headline tracking, approximately `-0.04em` to `-0.065em`.
- Use body line height between 1.55 and 1.8.

Technical label typeface: **DM Mono**

- Use weights 400–500.
- Use for labels, dates, indexes, categories, metadata, and technical annotations.
- Use uppercase sparingly with `0.05em` to `0.08em` tracking.

Fallbacks:

- Manrope: `system-ui`, `-apple-system`, `BlinkMacSystemFont`, `Segoe UI`, sans-serif.
- DM Mono: `ui-monospace`, `SFMono-Regular`, `Consolas`, monospace.

Use no more than these two type families in a personal-brand asset. Employer-branded material may use the employer's approved typeface instead.

### Wordmark and signature

The personal wordmark is **MA** in a heavy Manrope-style weight with tight letter spacing and a small dot.

- Preferred wordmark: Ink `MA` with a Warm orange dot.
- Reversed wordmark: White `MA` with a Warm orange or Acid lime dot on Ink.
- Keep clear space around the wordmark equal to the height of the dot on all sides.
- Do not stretch, outline, rotate, add effects to, or place the wordmark inside another logo.
- Do not typeset the full name as a corporate logo. Use the wordmark as a signature and “Md Abir” as ordinary text.

The favicon uses a compact `M` monogram with an Acid lime dot. Treat this as the small-format exception, not the standard wordmark treatment.

### Shape language

- Use thin one-pixel borders in Line or low-opacity White.
- Use generous rounded corners: 14px for small components, 24px for cards, 36px for large panels.
- Use pill shapes for compact labels, statuses, and actions.
- Use large cropped circles or rings as quiet background geometry.
- Use a short Acid lime marker or underline to emphasize one phrase.
- Use soft shadows only for raised proof cards or primary panels. Preferred shadow: `0 28px 70px rgba(26, 30, 21, 0.12)`.

Do not use glass effects as the main visual language. Do not use decorative blobs, neon glows, fake terminal windows, or generic AI brain imagery.

### Layout

- Use generous whitespace and a clear reading order.
- Prefer an asymmetric 60/40 or 65/35 split for hero compositions.
- Align text to a consistent left edge.
- Use a maximum content width near 1180px for web layouts.
- Keep one dominant message per composition.
- Use borders and grid lines to organize evidence instead of adding more color.
- Let important numbers or proof points occupy their own cells.

For responsive layouts, preserve the hierarchy before preserving the exact composition. Stack columns, reduce headline size, and keep touch targets at least 44px high.

### Photography and imagery

Preferred imagery, in order:

1. Real product screenshots or interface details.
2. Real diagrams of workflows, architecture, or data movement.
3. Project logos used in a structured neutral panel.
4. A current professional portrait.
5. Abstract geometry derived from the brand's circles, grids, and marker line.

Portrait treatment:

- Use a natural crop with clear eye line and breathing room.
- Keep colors slightly restrained rather than heavily saturated.
- Avoid artificial background replacement unless requested.
- Do not generate a synthetic portrait when a real photograph is available.

Avoid generic stock photos, humanoid robots, glowing brains, circuit-board faces, floating dashboards, handshake photos, and decorative code that is not real.

## Social-media asset system

These are production templates for this brand, not claims about platform upload limits.

### Recommended canvases

- Link preview / Open Graph: 1200 × 630px.
- Portrait social post: 1080 × 1350px.
- Square social post: 1080 × 1080px.
- LinkedIn profile cover: 1584 × 396px.

Keep essential text and faces at least 7% of the canvas width away from each edge. For profile covers, keep the left 30% visually quiet because profile photos and interface elements may overlap it.

### Template A: insight card

Use for one practical lesson.

- Small DM Mono category label at the top.
- One Manrope headline, ideally 6–14 words.
- One Acid lime marker under a short phrase.
- Optional one-line context at the bottom.
- MA wordmark in a corner.

### Template B: project evidence card

Use for a case study or result.

- Project name and role as metadata.
- One large result or system decision.
- One supporting sentence explaining what changed.
- Product screenshot or logo in a bordered panel.
- Technology names may appear as small tags, limited to the most relevant four or five.

### Template C: workflow or architecture card

Use for AI automation, data engineering, and system explanations.

- Show a left-to-right or top-to-bottom flow.
- Use Ink for nodes, Line for connectors, and Acid lime for the active or improved step.
- Use Warm orange only for a warning, constraint, or manual handoff.
- Label every arrow with the actual event, data, or decision it represents.

### Template D: career update

Use for a role, education, or speaking update.

- Lead with the factual update.
- Use a portrait or employer-approved logo only when appropriate.
- Keep employer branding separate from the personal system.
- Do not imitate an employer's brand or place the MA wordmark inside an employer lockup.

### Social-card copy limits

- Use one headline.
- Use no more than two supporting text blocks.
- Prefer one proof point to several weaker claims.
- Keep body copy readable without zooming.
- Put details, links, and context in the post caption rather than shrinking them onto the image.

## Employer and partner branding

The personal system and the Hasso Plattner Foundation visual identity are separate.

- Use HPF colors, type, logos, and templates only for material that is specifically about HPF and only when their use is permitted.
- Use the official HPF logo asset without redrawing or recoloring it.
- Do not mix the personal Acid lime and Warm orange palette into an HPF-branded composition unless an approved co-brand layout calls for it.
- For a personal post about HPF, choose one visual owner: either an HPF-led card with a discreet personal attribution, or a personal-brand card that names HPF in text without imitating its identity.
- Apply the same separation to any future employer, client, university, or partner.

## Writing style

Write in first person when the asset represents Md Abir directly. Use plain, specific language.

Preferred structure:

1. State the problem or observation.
2. Explain what was built or changed.
3. Give the result, constraint, or lesson.

Use:

- “I built…”
- “The process relied on…”
- “The system reduced…”
- “The main constraint was…”
- “I chose this approach because…”

Avoid:

- inflated claims such as “revolutionary,” “game-changing,” or “world-class”;
- generic openings about the fast-changing world of AI;
- long tool lists without context;
- claims that cannot be checked;
- excessive emoji, hashtags, exclamation marks, or decorative punctuation;
- describing concepts, drafts, or learning exercises as production systems.

Use “AI” only when an AI component is part of the work. Use “automation” for deterministic workflows, integrations, and rules-based systems. Use “AI automation” when both are present.

## Data visualization and diagrams

- Start with the question the chart or diagram must answer.
- Use Ink for primary data and Muted for context.
- Use Acid lime for one selected series, result, or state.
- Use Warm orange for exceptions, risk, or a manual bottleneck.
- Label values directly when possible.
- Remove decorative legends, 3D effects, heavy gridlines, and unexplained icons.
- Do not imply precision that the source data does not support.

## Motion

- Use motion to clarify hierarchy or state changes.
- Prefer short fades and vertical movement between 180ms and 700ms.
- Use restrained easing and no continuous decorative animation.
- Respect `prefers-reduced-motion`.
- Never delay access to the main message for an animation.

## File and export rules

- Work in sRGB.
- Export text-heavy cards as PNG.
- Use high-quality JPEG or WebP for photography when transparency is not needed.
- Keep an editable source beside each final export.
- Use descriptive filenames: `md-abir-[channel]-[topic]-[format]-YYYYMMDD.ext`.
- Do not overwrite an approved final asset without preserving the previous version.

## Required quality checks

Before delivering an asset:

- Confirm the name, employer, role, dates, metrics, and links.
- Check that the work is labeled accurately as shipped, in progress, or exploratory.
- Verify contrast and readability at the intended display size.
- Check safe areas and likely social-media crops.
- Confirm that only approved logos and photographs are used.
- Remove unsupported claims and generic filler.
- Check spelling, punctuation, alignment, and export dimensions.
- Compare the result with the portfolio at `index.html`.

## Instructions for AI systems

When asked to create a personal-brand asset for Md Abir:

1. Read this file and `brand-tokens.json` before designing or writing.
2. Identify the asset type, audience, channel, and one message it must carry.
3. Use the defined colors, typography, spacing, shapes, and writing style.
4. Reuse existing photographs, logos, and project assets where appropriate.
5. Keep personal branding separate from employer and partner identities.
6. Ask for missing facts only when they would materially change the result. Never invent them.
7. Produce an editable source and the requested export when the format allows it.
8. Run the required quality checks before delivery.

If no format is specified for a social card, default to 1080 × 1350px. If no visual direction is specified, use Paper as the background, Ink for type, one Acid lime marker, one Warm orange micro-accent, and the MA wordmark.
